# DCMM 专家级审计红线与质量标准 (V3.1)

## 核心原则

**宁可漏判，不可错杀。** 一票否决必须办成铁案——证据确凿、多处印证、无合理反驳空间。不是铁案的一律标为红线质疑。错杀的后果远大于漏判。

---

## 一、一票否决红线（不通过）

### 铁案标准

判定一票否决需同时满足：
1. **位置在已提交材料内**：问题出现在甲方已提交的任一治理文档（数据战略/治理/架构/质量/安全/标准/生存周期/提升建议）正文或打分表中，即视为核心位置；评估报告本身的引用语句、参考列表不算。
2. **无法合理解释**：不能用"学习了""借鉴""对标""参考了""研究了""标杆企业"等合理跨行业引用、集团内业务交叉、简称变体等解释。
3. **不要求多处印证**：对于"其他企业名称作为制度/办法/规范主语或文件命名"或"与企业行业明显矛盾的其他行业关键词"，单处确凿即可判一票否决；其余类型（如零星行业词汇）仍需多处印证。

### 1. 严重张冠李戴 / 套用模板

- 甲方报告中**任一已提交治理文档**（数据战略/治理/架构/质量/安全/标准/生存周期/提升建议）正文或打分表中，出现与企业自身行业**明显矛盾**的其他行业特征关键词（如制造企业出现"门诊""病历"、船舶设计院出现"软件和信息技术服务行业""互动直播部"），即判一票否决；不要求系统性多处出现，单处明显矛盾即可。
- **注意区分**：
  - 集团下属企业提到集团内其他业务的术语（如炼化企业提到"油气井"）属于正常的集团内交叉引用，不算张冠李戴
  - **排除合理引用**：出现在"学习了""借鉴""对标""参考了""研究了""标杆企业""跨行业""等企业"等表述中、作为跨行业案例或集团交叉引用提及的，不算张冠李戴。
- 甲方报告**任一已提交治理文档**正文或打分表中，以**制度/办法/规范的主语或文件命名**出现其他企业名称（非简称变体、非评估机构、非其自身客户），即判一票否决，不要求多处印证。如：制度正文写"广州方维信息技术有限公司《数据质量需求管理办法》旨在…"、提升建议写"建议长春嘉诚进一步…"、数据仓库规范命名为"OPPEIN-BI"。
- 数据战略或治理制度为**纯模板**，通篇无任何企业自身行业特征。

### 2. 数据战略和/或数据管理制度内容严重错误

- 数据战略描述**通篇抽象通用**（如只有"提升数据管理水平"等空话），且无系统截图支撑其实际落地。注意：有部分通用描述+有部分企业特征的不算严重错误。
- 将**《数据管理文件控制制度》（文控管理）**当作《数据管理办法》——需确认是真正把文控制度当数据管理制度，而非文件中偶尔提到文控。
- 出现**"数据战略制度管理办法"**等命名混乱，反映出对DCMM概念理解严重错误。

### 3. 数据质量域无任何系统截图

- 07数据质量.pdf中**所有页面均无系统截图**。
- 判定方法：检查每页的图片标注。如果页面标注了[本页含N张图片]，说明有图片，不能判"完全缺失"。
- 如果07域有图片但只是文档扫描件（非系统截图），标为红线质疑而非一票否决。

### 4. 数据架构域明显Demo/网图

- 截图**明显**为产品Demo：含占位符（"测试数据""example"）、通用测试数据、无企业专属标识。
- 注意：截图"不够充分"≠"明显Demo"。截图有企业名称但内容简单，标为一般性问题。

### 5. 乙方合同纯度不足

- 企业作为乙方，提供的合同中**没有任何数据管理/数据治理类合同**。
- 需要至少有**两个**来自不同客户的数据治理相关合同。
- 注意：有部分系统集成合同+有部分数据治理合同，不算纯度不足，标为一般性问题。

## 二、重大质疑（整改项，不直接否决）

以下问题**不作为一票否决**，标为红线质疑，严重的建议复审，轻微的建议修改。

### 1. 红头文件 / 发文证据
- 顶层办法未见红头公章与发文时间——可能因文本提取和图片抽样未覆盖，不等于真没有。
- 如果文本出现"红头""发布""发文""管理办法"等关键词且页面有图片，必须标注页码供视觉验证，不能判缺失。

### 2. 制度年限不足
- 数据战略或治理组织设立时间距评估不满一年。

### 3. 物理表冒充逻辑模型
- 将数据字典/物理表当作逻辑模型——需定性为重大整改。

### 4. 跨业务域证据不足
- 系统截图集中在单一业务域，缺跨域闭环管理证据。

### 5. 数据安全外部审计缺失

### 6. 其他
- 零星出现其他行业关键词（1-2处）、组织架构不够清晰等——标为红线质疑或一般性问题。

## 三、最终结论判定规则

### 审计结论（四选一）

| 审计结论 | 说明 |
|---------|------|
| 踩红线（一票否决） | 触发第一节5类绝对红线，满足铁案标准 |
| 红线质疑 | 存在重大质疑项，需企业整改或补充证据 |
| 一般性问题 | 非红线级缺陷，建议改进 |
| 无 | 未发现重大问题 |

### 最终结论（四选一）

| 最终结论 | 判定规则 |
|---------|---------|
| 不通过 | 触发一票否决红线；或多项红线质疑且确凿；或严重有悖逻辑常理 |
| 复审 | 红线质疑比较确凿（1-2项），需现场复审验证 |
| 修改 | 有红线质疑但只有1-2个点、或有其他非关键问题，企业修改后可过 |
| 通过 | 问题不大或没有问题 |

### 输出格式

报告末尾必须包含：
**审计结论**：[踩红线（一票否决）/红线质疑/一般性问题/无]
**最终结论**：[不通过/复审/修改/通过]
